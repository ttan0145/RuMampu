# Epic 2 用户故事与验收标准

- 范围：4 个用户故事、18 条验收标准

## US2.1 — 逐月查看收入

**用户故事：** 作为收入不规律的用户，我希望看到各记录月的可用收入，以理解收入随时间变化的程度。

- **AC2.1.1 — 显示月度收入图：** 已记录一个或多个月收入时，打开 Income pattern 后，应显示逐月收入可视化。
- **AC2.1.2 — 显示月份标签：** 图中包含多个月份时，每个 bar 都对应一个带标签的记录月。
- **AC2.1.3 — 反映不同月度金额：** 各月金额不同时，bar 高度应反映这种差异。

## US2.2 — 理解典型月份与极端月份

**用户故事：** 作为用户，我希望看到记录收入的汇总统计，以理解典型月份以及较强、较弱月份之间的差距。

- **AC2.2.1 — 显示平均收入：** 存在月度收入时，Income pattern 显示平均值。
- **AC2.2.2 — 显示中位收入：** 收入摘要显示记录收入的中位数。
- **AC2.2.3 — 显示最高收入：** 收入摘要显示最高记录月收入。
- **AC2.2.4 — 显示最低收入：** 收入摘要显示最低记录月收入。
- **AC2.2.5 — 标识计算结果：** 从用户记录推导出的统计值必须标为“计算所得”。
- **AC2.2.6 — 解释波动：** 收入形态存在月度差异时，界面使用可见的记录范围说明波动程度。

## US2.3 — 识别较低收入月份

**用户故事：** 作为用户，我希望 RuMampu 在我的记录历史中识别较弱收入月份，以便将其与更典型的月份区分开。

- **AC2.3.1 — 使用记录历史规则：** 存在月度收入时，RuMampu 根据记录历史识别较低收入月，不使用固定百分比阈值。
- **AC2.3.2 — 解释识别方式：** 界面说明结果来自用户记录历史，不是金融标准。

## US2.4 — 检查记录是否覆盖通常较慢的时期

**用户故事：** 作为收入可能随季节变化的用户，我希望标出通常收入较少的月份，以了解当前记录是否包含这些时期。

- **AC2.4.1 — 询问较慢时期：** 打开 Coverage check 时，询问一年中是否存在通常收入较少的时期。
- **AC2.4.2 — 提供三个选项：** 可以选择 Yes、No 或 Not sure。
- **AC2.4.3 — 选择慢月份：** 选择 Yes 后，12 个月都可以选择。
- **AC2.4.4 — 选择多个慢月份：** 多个月份可以同时保持选中。
- **AC2.4.5 — 警告未覆盖月份：** 用户声明的慢月份不在记录中时，提示尚未覆盖。
- **AC2.4.6 — 确认已覆盖月份：** 用户声明的慢月份存在于记录中时，明确显示已覆盖。
- **AC2.4.7 — 回应 No 或 Not sure：** 仅显示当前记录中的事实性范围观察，不据此确认季节代表性。

## 校准后的计算边界

- 可用收入等于每月总收入减去同一日历月已记录的工作成本。
- 返回平均数、中位数、最高、最低、范围与总体标准差；只有一到两个月时继续显示事实值，并明确提示历史有限。
- 至少有两个记录月时，较低收入月是所有并列的记录最低月；它不是预测或金融标准。
- Coverage 将用户声明的慢月份与实际记录日历月份比较。`No` 与 `Not sure` 只返回事实性记录范围，不能确认季节代表性。
- 固定百分比规则、变异系数评分、无来源阈值和 Low/Moderate/High 风险标签均不在批准范围内。
