# ADR 0004：住房计算以后端为权威

语言：**中文（CN）** | [English](0004-backend-authoritative-housing-calculations.md)

- 状态：已接受
- 日期：2026-08-28

## 背景

后端已经负责融资计算、住房前置检查和历史住房测试服务，但正式前端仍会把客户端计算出的财务月份提交给无状态端点，`calc.ts` 中保留重复住房公式，并可能通过 `preHousingOk()` 独立于服务端结果决定路由。因此首页、测试页和准备页可能与 Django 得出不同结论。

## 决策

1. Django 是以下计算的唯一权威层：融资额、月供、房屋月总成本、住房前残余、历史测试、短缺、承担区间、参考房价换算、付款比较、收入下降情景、前期资金缺口与起始缓冲金。
2. 正式前端创建或更新当前 session 归属的 `HousingScenario`，请求 `/housing/pre-check/`，再按 scenario ID 调用 `/housing/test-result/`。
3. 导航和展示都使用保留的服务端响应；前端不再独立推导财务结论。
4. 付款比较和收入冲击是测试请求中的可选、非持久化覆盖值。它们复用已保存 scenario 与权威财务记录，不修改任一事实。
5. `/housing/test/` 为 v1 兼容继续保留，但正式前端不再调用，也不再提交客户端计算的财务月份。
6. 格式化、图表位置、翻译、导航机制和瞬时 UI 状态仍由前端负责。

## 影响

- 住房前置路由和导航后的展示值使用同一后端结果。
- 住房公式由 Django 测试覆盖，并体现在 OpenAPI 中。
- 访客 session 中可以存在 scenario；前端重复测试时更新已保留的 scenario，而不是每次新建一行。
- 依赖历史测试的准备页会提示用户先运行测试，不再静默回退到本地公式。

## 修订 2026-10-09

决策第 1 条把“前期资金缺口与起始缓冲金”列为后端权威。就前期资金缺口而言，后端的实际范围是：对客户端提供的成本项（首付加上提交的 `upfront_costs`）求和并计算缺口。这些成本项的金额（转让与贷款印花税、律师费、估价费、首套房豁免）以及 pot 分配规则由客户端计算，见 [ADR 0006](0006-client-side-upfront-fees-and-pot-allocation.cn.md)。起始缓冲金不变，仍由后端计算（见 [ADR 0005](0005-cash-buffer-deepest-fall.cn.md)）。以上原文保持不变。
