# ADR 0002：后端权威的收入形态分析

语言：[English](0002-backend-authoritative-income-pattern.md) | **中文（CN）**

- 状态：已接受
- 日期：2026-08-25

## 背景

早期原型在前端计算收入形态，并包含缺乏依据的阈值。Epic 2 的结果会被后续住房与准备流程使用，因此客户端各算一套会产生漂移和相互矛盾的结论。

## 决策

1. `GET /api/v1/income-pattern/` 是权威计算边界。
2. 应用服务按日历月聚合收入，每月只扣一次当前有效工作成本快照，并以 `Decimal` 计算描述统计。
3. 总体标准差只在响应边界按 `ROUND_HALF_UP` 保留两位。
4. 源记录与派生分析分离；派生分析实时重算，不持久化快照。
5. 至少存在两个记录月时，所有并列记录最低月均为较低收入月；不生成固定阈值、评分、预测或风险带。
6. `GET/PUT /api/v1/income-coverage/` 仅持久化当前访客的明确回答。`yes` 要求唯一的 1–12 月份；`no` 与 `not_sure` 清空月份列表。
7. Coverage 比较用户声明月份编号和实际记录的日历月份编号；`no` 与 `not_sure` 只返回事实性的记录范围。
8. 前端只消费 typed response，并处理 loading、ready、saving、error、empty、limited-history 与 retry 状态。保存失败时保留上一次服务器确认的回答。

## 影响

- Web、移动端和未来客户端共享同一个计算协议。
- 在历史工作成本需求获批前，当前工作成本会明确应用到全部记录月。
- 修改收入或当前工作成本后，下次响应会重新计算，不需要迁移或清理分析快照。
- 除非能由用户声明与记录月份直接推出，否则季节代表性保持未知。
