# 真实线上网站测试

语言：**中文** | [English](LIVE_WEBSITE_TESTS.md)

脚本通过 Chromium 操作真正部署的 `https://rumampu-frontend.vercel.app/`，
并验证 `https://rumampu.vercel.app/api/v1` 的响应。不启动本地网站，不模拟接口，
不调用开发数据重置接口，不执行迁移，也不修改 LeanKit。
脚本本身不调用 AI；平时自己运行，失败时再把报告交给 Codex 分析即可。

## 怎么运行

在 `RuMampu/frontend` 目录打开终端，电脑需有 Node.js/npm：

```sh
# 首次准备；依赖变动后重新安装
npm ci
npx playwright install chromium

# 日常只读检查：不保存收入、工作成本或住房方案
npm run test:live

# 明确允许写入独立访客的模拟数据，跑完整流程
npm run test:live -- --allow-writes

# 打开 Chromium 窗口，观看脚本自动操作
npm run test:live -- --allow-writes --headed

# 打开最近一次报告
npm run test:live:report
```

`npm run test:live -- --help` 显示帮助；`--list` 只列出测试，不开浏览器。
退出码 0 表示所选测试通过，非 0 表示测试或环境准备失败；未知参数会被拒绝。

## 安全边界与报告

- 每次新建浏览器上下文及随机 `live-smoke-...` 访客 ID，不导入现有浏览器、
  登录态或用户数据。开始前确认该访客没有收入、成本记录和住房方案。
  同时验证真实页面的接口响应来自指定后端、使用同一个独立访客 ID。
- “只读”指**不写入财务记录**，并非数据库完全零写入：RuMampu 首次访问会
  创建匿名访客和默认类别。住房预览使用不保存方案的计算 POST；结束时再次
  核对收入、成本、住房方案均为空。
- `--allow-writes` 通过真实界面新增一笔 RM 3,000 收入、两笔 Petrol 成本和一个
  住房方案。日期取后端当前月份及上月的 1 日，不写死 2026 年 9 月。
  第一笔成本从 RM 50 改成 RM 60 后移到上月；本月留下 RM 25。
- **模拟数据保留在生产数据库的独立访客中**，失败的流程也可能留下部分记录。
  脚本不会执行清库、删除、迁移或复用上一次访客。日常用只读模式，完整写入
  流程按需运行，避免无意义地积累模拟数据。
- 仅一个 worker，禁用自动重试。写入流程失败后先看失败步骤，不要连续盲目重跑。
- 最新 HTML 报告：`output/playwright/live/report/index.html`；结构化结果：
  `output/playwright/live/report/results.json`。报告附成功步骤截图、接口状态与
  访客清单；失败截图和 trace 位于 `output/playwright/live/test-results/`。
  输出不进入 Git，下一次运行会覆盖；需要留档时先复制报告目录。
- 报告和 trace 内含模拟访客标识，应作为私有资料保存；不要将原始 trace 或访客
  ID 发到公开 issue。
- 原来的 `npm run test:e2e` 和 CI 仍然只测本地。线上测试使用独立目录和配置，
  不会被默认回归命令意外触发。
